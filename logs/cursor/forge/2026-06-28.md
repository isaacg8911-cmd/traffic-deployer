## Upload fix — legacy .xls silently dropped (Week 16 trial files)

- Report: Director uploaded `Week 16 Isaacx.xls` + `Week 16 Day 1 Isaac.est`; "it didn't work".
- Root cause: both files are OLE2/legacy binary (magic `D0 CF 11 E0`). `.xls` needs pandas
  engine `xlrd`, which pandas imports lazily at `read_excel` time. PyInstaller static
  analysis misses lazy engine imports, so the frozen/portable build (and any partial venv)
  has no `xlrd`. `core.ingest.parse_excel_sites` swallowed the `ImportError`
  (`except Exception: continue`) and returned 0 sites → BUILD showed the misleading
  "No site coordinates found in the Excel/CSV", i.e. upload "didn't work".
- Failed: missing-engine path returned 0 sites silently.
- Changed:
  - `core/ingest.py`: added `ExcelEngineMissing` + `_engine_hint()`; `parse_excel_sites`
    now re-raises a clear, actionable error on `ImportError` instead of dropping all sites.
  - `ui/controllers/route.py` + `ui/controllers/setup.py`: catch `ExcelEngineMissing` and
    show the hint (BUILD path + road-download `_gather_area_points` guard).
  - `traffic_deployer.spec`: added `pandas`, `xlrd`, `openpyxl`, `xlsxwriter` to
    `hiddenimports` so the portable build can read `.xls`/`.xlsx` and export.
  - `START.bat`: dependency self-check now imports `xlrd, openpyxl, xlsxwriter` so a
    partial venv triggers a repair install.
- Coder proof (`.venv`):
  - Real Week 16 files: `parse_excel_sites` → 57 sites; `match_est_files` → 57 stops;
    `validate_build` ok; routing optimize 57/57, build_route on graph.
  - Error path: simulated frozen build with `xlrd` blocked → now raises
    `ExcelEngineMissing` ("This .xls file needs the 'xlrd' package…") instead of 0 sites.
  - `python scripts/smoke_full.py` → SMOKE PASS (all green, no regressions).
- Not proven: portable `.exe` not rebuilt this session — spec fix needs
  `BUILD_PORTABLE.bat` / `BUILD_WORK_LAPTOP.bat` to bake the engines into the frozen build
  before the work-laptop upload is end-to-end proven.

## Phone "switch apps & come back" lost the job on public hosts

- Root cause: all field edits already persist to the server in real time (every install/grab/
  patch/move POSTs immediately), BUT the PWA `finishBoot()` cleared the saved session and
  showed the start screen for ANY public-mode load without a `/join` URL. After opening a
  job the app cleans the URL to `/` (history.replaceState), so a reload / app-switch return
  hit the bare URL → session wiped → job looked lost (it still existed server-side). That
  guard was meant for share-only crew phones, not the operator's own open-uploads phone.
- Failed: public bare-URL reload dropped to start screen even with a remembered job.
- Changed:
  - `mobile_web/static/app.js` `finishBoot()`: only clear session on `publicMode && !canCreate`
    (pure share-only). In open-uploads mode (operator's own phone) OR local mode, reopen the
    remembered job from localStorage so app-switch/reload/lock never loses the shift.
  - Cache-bust: `index.html` `app.js?v=9`→`v=10`; `sw.js` shell `v6`→`v7`.
- Coder proof: `python scripts/mobile_app_check.py` → PASS (user 26/26, TLS 11/11, share
  32/32, stress p95≈5ms). No regressions. Lints clean on app.js.
