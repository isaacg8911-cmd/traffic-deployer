## [Cursor Log] Build/Order blocked by "road map hasn't downloaded" — DEMAND

**Symptom (Director):** "I cannot choose the order of my sites. When I Build I get a notice that the roadmap hasn't downloaded. Downloading roadmaps — nothing in the UI works." Field-flustered; wants efficient + effortless.

**Root cause:** `SIMPLE_MODE = True`, so **Build** auto-optimizes. Both build entry points hard-`return`ed unless a road map was loaded:
- `ui/controllers/route.py` `_optimize_and_route` — blocked before building.
- `ui/controllers/route.py` `_route_pick_apply` — blocked applying a *manually chosen* order.

The routing engine already builds a valid **straight-line** route with real miles when no graph is present (`routing.optimize`, `routing.build_route`, `map_display.apply_manual_order` all handle `graph=None`). The gate was pure friction — it prevented ever choosing/building a route without a download. Separately, on blocked corporate Wi‑Fi the osmnx download hung `requests_timeout=300s × 5 Overpass mirrors ≈ 25 min` before failing → "nothing works."

**Fix (never block the route):**
- `route.py` `_optimize_and_route` — removed hard block; if no graph, non-blocking status note and build straight-line. Progress dialog reworded ("Building route order…").
- `route.py` `_route_pick_apply` — removed hard block; a chosen order always applies (straight-line if no graph), non-blocking note.
- `route.py` `_optimize_and_route` done() — pure no-graph case now a status note, not a modal popup (kept the `graph_uncovered` "downloaded map is for the wrong area" modal — that one matters).
- `road_router.py` `_configure_osmnx_for_download` — `requests_timeout`/`timeout` 300 → **75s** so blocked Wi‑Fi fails fast instead of hanging ~25 min.

Road map is now an **optional upgrade** (real streets), not a prerequisite. Straight-line order + miles work with zero setup.

**Proof:**
- `scripts/smoke_full.py` → `SMOKE PASS` exit 0.
- `scripts/test_route_pick_clicks.py` exit 0 (drag-reorder "start from the top" honored; applied order matches chosen top stop).
- Empty-data-dir check: `optimize` graph=False orders 3 stops (6.57 mi); `apply_manual_order` honors chosen `[3,1,2]` exactly (9.48 mi) — order + build with **no** road map.

**Note for Director:** the "lines on the map" are the site segment lines (Excel begin→end) and the route line between stops. Without a road map the route line is straight (as-the-crow-flies) but the **stop order and mileage are still computed**; downloading/importing a road map only redraws it along real streets.

**Shipment verification (Director asked "is the extracted package always tested?"):** No — `smoke_full.py` (default prove) tests **dev source**, not the frozen bundle. The shipped package (`dist/TrafficDeployer-AppUpdate`) was **19h stale** vs today's fix.
