## [Cursor Log] DEMAND: GPS grab / Drop pin lands on previous site

**Field report:** skip Install, tap next site, Grab GPS → saved on the previous site.

**Root causes found (click-order audit):**
1. `_route_item_clicked` (left route list) set `current_index` directly while on Install — no form flush, Drop pin stayed on. Next Install/end-pin read the OLD site's orange pin and saved it to the NEW site.
2. `web/app.js` field pin had no owner check: in Drop pin mode a site without coords kept the previous site's pin; `placeFieldPin` "same" shortcut ignored uid; `__tdSetFieldPin` took uid from stale `lastState`.
3. `_select_install_stop` in Drop pin mode switched index only after the async JS pin read — Grab GPS in that gap (or a JS callback that never came) saved to the previous site.
4. Undo changed site without ending Drop pin.
5. No proximity sanity check on grab/drop.

**Fixes:**
- `ui/controllers/install.py`: site switch is synchronous; `_end_manual_grab` binds the final pin read to the old site uid, turns map taps off immediately, `_pin_flush_busy` guard + 1.5 s fallback; `_save_field_position(uid=)` writes one site and only updates labels/pin for the site on screen; Install/Grab/Clear/Drop blocked while a pin flush is pending; commit re-checks uid.
- `core/site_window.py` (new): distance to site segment; prompt when a point is >300 m from the chosen site and another site is clearly closer, or >1.5 km away.
- `ui/controllers/route.py`: route list click on Install → `_select_install_stop`.
- `ui/controllers/shortcuts.py`: Undo ends Drop pin first.
- `web/app.js` + `bridge.py`: pin carries uid; foreign pin cleared on site change; confirm returns uid (Python rejects mismatch).
