# Forge log — 2026-09-23

## [Cursor Log] Manual pick clicks never reached Apply

**Demand:** v1.0.17 still will not apply a manual pick order. Look at the update and run the tests.

**Root cause:** Pick mode and Apply are in the 1.0.17 exe. On the work laptop the map click bridge often never connects, so the page falls back to a URL. That URL was `tdstop://` plus the site id (`Day 1_101|begin`). Qt treats that as an invalid hostname (`%` and `|` are illegal), and WebEngine drops custom schemes before the page hook. The click arrives empty, the order stays empty, and Apply stays off. Auto-build does not need a click, so Build still automates.

**Changes:**
- Dot clicks fall back to `http://tdstop.local/pick?p=uid|side`, which the page cancels and reads.
- Empty-map clicks use the same pattern (`http://tdmap.local/point`).
- The click test now disconnects the real page bridge (a page-global `bridge = null` was a false pass) and requires the fallback payload.

**Error path:** Invalid old `tdstop://` host form still yields an empty payload. A down bridge no longer loses `uid|begin`.

**Proof:** `scripts/test_map_click_delivery.py` exit 0 (bridge click + http fallback + map-click fallback). `scripts/test_route_pick_clicks.py` exit 0. `scripts/verify_frozen_bundle.py` exit 0 — shipped 1.0.17 contains pick UI, not this click fix.

**Ship:** Commit local; push skipped (branch `main`). Laptop still on 1.0.17 until the next package.
