## [Cursor Log] Manual pick clicks never reached Apply

**Demand:** v1.0.17 still will not apply a manual pick order. Look at the update and run the tests.

**Root cause:** Pick mode and Apply are in the 1.0.17 exe. On the work laptop the map click bridge often never connects, so the page falls back to a URL. That URL was `tdstop://` plus the site id (`Day 1_101|begin`). Qt treats that as an invalid hostname (`%` and `|` are illegal), and WebEngine drops custom schemes before the page hook. The click arrives empty, the order stays empty, and Apply stays off. Auto-build does not need a click, so Build still automates.

**Changes:**
- Dot clicks fall back to `http://tdstop.local/pick?p=uid|side`, which the page cancels and reads.
- Empty-map clicks use the same pattern (`http://tdmap.local/point`).
- The click test now disconnects the real page bridge (a page-global `bridge = null` was a false pass) and requires the fallback payload.

**Error path:** Invalid old `tdstop://` host form still yields an empty payload. A down bridge no longer loses `uid|begin`.

**Proof:** `scripts/test_map_click_delivery.py` exit 0 (bridge click + http fallback + map-click fallback). `scripts/test_route_pick_clicks.py` exit 0. `scripts/verify_frozen_bundle.py` exit 0 — shipped 1.0.17 contains pick UI, not this click fix.

**Ship:** Commit local; push skipped (branch `main`). Laptop still on 1.0.17 until the next package.

## [Cursor Log] BUILD ROUTE site click did not start the order

**Demand:** After BUILD ROUTE, clicking a site still does not start the pick order. Prior updates reported success without changing that.

**Root cause:** Two gates dropped the first click while the UI still changed.
1. If the map already had a saved line, pick mode stayed on but `_section_pick_active` was false. The click only rewrote the status bar. The order list did not gain stop 1.
2. The map toast announced a stop number before Python accepted the click. When QWebChannel `onStopClick` existed but did not deliver, the toast was the only change. The http fallback never ran.

**Changes:**
- BUILD clears this map's saved line before the first click.
- A site click during pick always adds stop 1, including when the map looked already applied.
- Site clicks always use `http://tdstop.local` (the path that actually arrives). The toast no longer claims a stop that is not in the order.
- The order window no longer opens on top of the map or steals the click.

**Error path:** A site on the other map is still rejected once this map already has picks. A click far from every site still does not add a stop. A bogus uid still reports "not in this job".

**Proof:** `scripts/test_route_sections.py` exit 0 (first click starts the order when a stored route made the map look applied). `scripts/test_route_pick_clicks.py` exit 0. `scripts/test_map_click_delivery.py` exit 0 (dot click arrives via http even while the bridge is connected). `scripts/smoke_full.py` exit 0.
